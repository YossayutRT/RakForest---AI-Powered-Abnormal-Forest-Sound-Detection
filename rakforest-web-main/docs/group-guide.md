# คู่มือสำหรับเพื่อนในกลุ่ม

เอกสารนี้จัดทำโดยทีม (ผู้พัฒนาส่วน Web App) สำหรับเพื่อนในกลุ่มที่ต้องการเข้าใจเว็บ แก้โค้ด หรือเชื่อมงานของตน เริ่มรันเว็บจาก [README หลัก](../README.md) ก่อน

## เครื่องมือและการตั้งค่า

- แนะนำ Node.js 24.x และ pnpm 11.25.0 ตาม `packageManager` ใน [package.json](../package.json)
- ใช้ `pnpm-lock.yaml` ร่วมกัน ติดตั้งด้วย `pnpm install --frozen-lockfile` ไม่ใช้ npm/yarn ติดตั้งซ้ำในโครงการนี้
- ไม่ต้องมี Python, โมเดล, Supabase หรือ Telegram เพื่อเริ่มโหมด mock
- ไม่ต้องมี `.env.local` สำหรับ mock หากจะเชื่อมโมเดล ให้คัดลอก [.env.example](../.env.example) เป็น `.env.local` และอ่าน [คู่มือ ML](ml-integration.md)
- `.env.local` ไม่ขึ้น Git ค่าลับต้องอยู่ฝั่งเซิร์ฟเวอร์ ไม่ใช้ชื่อ `NEXT_PUBLIC_` กับ API key
- Supabase/Telegram ใน `.env.example` ยังเป็น placeholder การเติมค่าอย่างเดียวไม่ทำให้เชื่อมใช้งาน

บน PowerShell คัดลอกค่าตัวอย่างด้วย `Copy-Item .env.example .env.local` หรือ macOS/Linux ใช้ `cp .env.example .env.local` หากมีไฟล์เดิมอยู่แล้วให้เปิดแก้เองแทนการคัดลอกทับ แล้วเริ่มเว็บใหม่หลังแก้ env

## ข้อมูลไหลอย่างไร

```text
เลือกเสา + ไฟล์เสียง
  → เก็บไฟล์และพิกัดเสาตอนอัปโหลดใน IndexedDB
  → AnalysisService เรียก POST /api/ml/analyze
  → mock: ให้ fixture / http: ส่งไฟล์ให้บริการโมเดล
  → ตรวจผลและเก็บแหล่งผล mock หรือ http
  → สร้างเหตุการณ์รอตรวจ
  → ส่วนกลางส่งงาน → ภาคสนามรับทราบ → ส่งผล → ส่วนกลางปิดงาน
```

สถานะงาน: `pending` รอตรวจ → `dispatched` ส่งงานแล้ว → `acknowledged` รับทราบแล้ว → `submitted` ส่งผลแล้ว → `closed` ปิดงาน ส่วนกลางปิดงานที่ยังรอตรวจโดยบันทึกเหตุผลได้

สถานะข้อความ Telegram แยกจากสถานะงาน ส่งข้อความล้มเหลวไม่ได้ทำให้งานหาย และส่งข้อความสำเร็จก็ไม่เท่ากับเจ้าหน้าที่รับทราบ

## สิ่งที่ต้องรักษาเมื่อแก้โค้ด

- ทุกหน้าใช้ข้อมูลชุดเดียวกันผ่านบริการ ไม่ใส่ fixture เพิ่มแยกไว้ใน component
- เสาเก็บพิกัดเป็น `[longitude, latitude]` ส่วนฟอร์มมีชื่อช่องชัดเจน ค่าที่กรอกต้องอยู่ในขอบเขตประเทศไทยจริงจากข้อมูลโครงการ
- งานเก็บสำเนาข้อมูลเสาตอนอัปโหลด การย้ายหรือปิดเสาภายหลังไม่เปลี่ยนตำแหน่งเหตุการณ์เก่า
- รีเฟรชระหว่างวิเคราะห์จะเก็บไฟล์ไว้และให้กดลองใหม่ ไม่ส่งซ้ำอัตโนมัติ ส่วนข้อความ/ภาพที่ยังไม่กดบันทึกในฟอร์มไม่ได้เก็บเป็น draft ข้ามการปิดหน้า
- ข้อมูลอยู่ในแต่ละ browser profile และ origin เช่น scheme/hostname/port การ clone โค้ดไม่ทำให้ข้อมูลผู้ใช้ในเบราว์เซอร์ตามไปด้วย
- ใช้ข้อความหลัก 18px ปุ่ม/ช่องกรอกอย่างน้อย 16px ข้อมูลประกอบอย่างน้อย 14px และพื้นที่กดอย่างน้อย 48px ไม่ลดตัวหนังสือบนมือถือเพื่อยัดหน้า
- แผนที่ฐานต้องใช้อินเทอร์เน็ต ข้อมูลขอบเขตไทยอยู่ในโครงการ ดู [แหล่งที่มาและสิทธิ์](../public/data/README.md) ห้ามลบเครดิตเดิม

## ทดสอบก่อนส่งงาน

ค่าเริ่มต้นชุดทดสอบคือ **Microsoft Edge บน Windows** ดู [playwright.config.ts](../playwright.config.ts) เว็บทั่วไปใช้พอร์ต 3000 ส่วนชุดทดสอบเริ่ม production server ของตัวเองบนพอร์ต 3100 และไม่ใช้เซิร์ฟเวอร์ที่เปิดค้างไว้แทน

```sh
pnpm typecheck
pnpm build
pnpm test
```

ถ้าเครื่อง Windows ยังไม่มี Edge ให้ติดตั้ง Edge ก่อน เครื่อง macOS/Linux รันเว็บได้ แต่การรันชุดทดสอบต้องมี browser ตาม channel `msedge` ใน config หรือปรับ config และติดตั้ง browser ที่กลุ่มตกลงกันก่อน ไม่ได้ตรวจข้ามระบบปฏิบัติการในรอบนี้

ตัวอย่างรันเฉพาะส่วน:

```sh
pnpm test tests/dashboard.spec.ts
pnpm test tests/ml-server.spec.ts
```

ถ้าพอร์ต 3100 ถูกใช้ ให้หยุดเฉพาะเซิร์ฟเวอร์ทดสอบที่กลุ่มเปิดค้างไว้ก่อน ไม่ต้องปิดเว็บพัฒนาพอร์ต 3000

ผลและ trace อยู่ใน `test-results/` ซึ่งไม่ขึ้น Git รูปที่ส่งมอบใน `docs/ui-accessibility/screenshots/` เก็บขึ้น Git ได้ตามเดิม ชุดทดสอบใช้ tile ทดแทนเพื่อไม่ส่งคำขอจำนวนมากไปยัง OpenStreetMap จึงไม่ได้ยืนยันความพร้อมของผู้ให้บริการแผนที่ภายนอก

[ผลตรวจล่าสุด](VERIFICATION.md) แยกจาก [ผลตรวจเก่า](history/verification-2026-10-17.md) เพื่อไม่ให้ความสามารถในคนละช่วงเวลาปนกัน

| --- | --- |
| โมเดลจริง | บริการ inference, preprocessing, คลาส/คะแนน และไฟล์ตัวอย่างตาม [คู่มือ ML](ml-integration.md) |
| ฐานข้อมูลกลาง / Supabase | บัญชีจริง สิทธิ์ข้อมูล งาน ไฟล์ และการย้ายข้อมูลจาก demo ตามที่กลุ่มตกลง |
