# เชื่อมโมเดลเสียงกับ RakForest

ตอนนี้เว็บใช้ `ML_PROVIDER=mock` เป็นค่าเริ่มต้น วิเคราะห์ด้วย fixture ตามเสา ไม่ได้อ่านเนื้อหาเสียงจริง การอัปโหลดและผลรอตรวจทำงานผ่าน API แล้ว ข้อมูลเสา เหตุการณ์ ไฟล์ และงานภาคสนามยังอยู่ใน IndexedDB ของเบราว์เซอร์เดียว Telegram ยังจำลอง

## ส่งอะไรให้ทีม (ผู้พัฒนาเว็บ) บ้าง

| สิ่งที่ต้องส่งหรือตกลง | ตัวอย่าง / เหตุผล |
| --- | --- |
| Framework และเวอร์ชัน | PyTorch / TensorFlow / ONNX ตามที่ใช้จริง เพื่อเตรียมบริการโหลดโมเดล |
| ไฟล์โมเดลและวิธีโหลด | เก็บในพื้นที่ที่กลุ่มตกลง ไม่จำเป็นต้องใส่น้ำหนักโมเดลลง repo frontend |
| URL ของ API วิเคราะห์ | URL เต็ม เช่น http://127.0.0.1:8000/analyze และวิธียืนยันตัวตนถ้ามี |
| รหัสคลาสและชื่อแสดงผล | ต้องตรงกับโมเดลจริง รวมลำดับคลาสหากบริการเดิมส่งเป็น array |
| รูปแบบเสียงที่รับได้ | sample rate, mono/stereo, ความยาว, ขนาดไฟล์ และ codec ที่ decode ได้ |
| Preprocessing | resample, แบ่งช่วง, spectrogram, normalization และวิธีรวมผลหลายช่วงให้ตรงกับตอนฝึก |
| เวอร์ชันโมเดลและความหมายคะแนน | คะแนนตามสัญญาเว็บอยู่ที่ 0–1 ไม่แปลงสเกลโดยเดาเอง |
| เสียงตัวอย่างพร้อมผลที่คาดหวัง | ทั้งเสียงปกติ คลาสต่าง ๆ และไฟล์ที่ควรถูกปฏิเสธ เพื่อทดสอบร่วมกัน |

**ต้องมีบริการ inference ที่โหลดโมเดลและ preprocessing ตรงกับตอนฝึก** การวางไฟล์ .pt/.h5/.onnx ในเว็บอย่างเดียวไม่ทำให้ใช้งานได้

## ตั้งค่าเว็บเมื่อ API พร้อม

ให้บริการของเพื่อนรับสัญญาด้านล่าง หรือแก้ตัวแปลงใน `src/lib/ml-server.ts` ให้ตรงกับบริการนั้น โดยให้ `parseModelResult` ตรวจผลก่อนส่งเข้าเว็บ ไม่เดาว่าคะแนน 90 หมายถึง 0.9 และไม่เดาลำดับคลาสจาก array

คัดลอก [.env.example](../.env.example) เป็น `.env.local` ในโฟลเดอร์รากของเว็บ แล้วตั้งค่า (หากมี `.env.local` อยู่แล้วให้เปิดแก้ ไม่คัดลอกทับ):

```dotenv
ML_PROVIDER=http
AI_CLASSIFICATION_ENDPOINT=http://127.0.0.1:8000/analyze
AI_CLASSIFICATION_API_KEY=
ML_TIMEOUT_MS=60000
```

หยุดและเริ่มเว็บใหม่ ค่า URL/key ไม่ถูกส่งให้เบราว์เซอร์ ปลายทางเป็น **URL เต็มของ endpoint วิเคราะห์** ส่วน API key ถ้ามีจะส่ง `Authorization: Bearer <key>` ตั้ง URL ฝั่งเซิร์ฟเวอร์เท่านั้น ตัวเชื่อมไม่ตาม redirect เมื่อบริการล่มจะไม่ใช้ mock แทน

## สัญญาคำขอและผล

`POST /api/ml/analyze` รับ multipart fields:

- `audio`: ไฟล์เสียงเดิม ไม่แปลง sample rate หรือ codec ในเว็บ
- `requestId`: รหัสอ้างอิงของความพยายามนี้ (1–100 ตัวอักษร a–z, A–Z, 0–9, _ หรือ -)
- `stationId`: รหัสเสา เป็นข้อมูลประกอบ ไม่ใช้แทนเสียงในโหมด http
- `simulateFailure`: ใช้เฉพาะ mock; http ไม่ส่งต่อให้โมเดล

Next.js ส่งสาม field แรกไปให้บริการโมเดล บริการต้องตอบ HTTP 200 พร้อม `Content-Type: application/json`:

```json
{
  "requestId": "test-001",
  "modelVersion": "forest-audio-v1",
  "label": "chainsaw",
  "scores": [
    { "classId": "chainsaw", "label": "เสียงเลื่อยยนต์", "score": 0.88 },
    { "classId": "bird", "label": "เสียงนก", "score": 0.12 }
  ]
}
```

`label` ระดับบนคือ **classId ที่ได้คะแนนสูงสุด**; กรณีเสมอเลือกหนึ่งในคลาสที่คะแนนสูงสุด คะแนนต้องเป็นตัวเลข finite ระหว่าง 0–1 คลาสไม่ซ้ำ ไม่บังคับผลรวมเท่ากับ 1 หรือจำนวนคลาสตายตัว (จำกัด 1,000 คลาสเพื่อป้องกันผลขนาดผิดปกติ) `label` ในแต่ละคะแนนไม่บังคับ: ถ้าไม่มี ใช้คำแปลที่เว็บรู้จัก แล้วใช้ classId เป็นข้อความสำรอง `requestId` ต้องตรงกับคำขอ

บริการหลายคลาสสามารถส่ง `decisionThreshold` และ `segments` เพิ่มได้ เพื่อแสดงคลาสที่ผ่านเกณฑ์และช่วงเวลาที่พบในหน้าเหตุการณ์:

```json
{
  "decisionThreshold": 0.5,
  "segments": [
    {
      "segmentIndex": 0,
      "startSeconds": 0,
      "endSeconds": 4,
      "scores": [
        { "classId": "vehicle", "label": "เสียงยานพาหนะ", "score": 0.72 },
        { "classId": "weather", "label": "เสียงสภาพอากาศ", "score": 0.81 }
      ]
    }
  ]
}
```

`segments` เป็นข้อมูลเสริมและอาจละได้ โดยแต่ละช่วงต้องมีคลาสชุดเดียวกับ `scores` ระดับไฟล์ คะแนนระดับไฟล์ของ API RakForest ปัจจุบันใช้ค่าสูงสุดรายคลาสจากทุกช่วง ส่วนหน้าเว็บรวมช่วงเวลาที่ติดกันและแสดงทุกคลาสที่มีคะแนนถึง `decisionThreshold` (ค่าปัจจุบัน 0.5 จาก checkpoint) เกณฑ์และคะแนนนี้ยังเป็นค่าทดลอง ไม่ใช่ threshold แจ้งเตือนที่ผ่าน calibration

สำหรับ multi-label model ให้บริการใช้คะแนน sigmoid แยกคลาส (ไม่ใช้ softmax) จึงมีได้หลายคลาสที่คะแนนสูงพร้อมกัน; ห้ามตีความ `label` ระดับบนเป็นเหตุการณ์เดียวที่ตรวจพบ โดยเว็บเก็บและแสดง score bars ของทุกคลาส แต่ `label` ใช้เป็นคลาสคะแนนสูงสุดสำหรับสรุป/ตัวกรองเดิม Threshold สำหรับทำรายการเหตุการณ์หรือแจ้งเตือนต้องตกลงและ calibrate แยกต่างหากก่อนใช้งานจริง.

เว็บเพิ่ม `source: "mock" | "http"` เองตามตัวประมวลผล ไม่เชื่อค่า source จาก upstream และบันทึกไว้กับผลถาวร `http` หมายถึงได้รับผลจากบริการ ไม่ใช่การรับรองความแม่นยำ

ตัวอย่าง PowerShell (เปิด Terminal ในโฟลเดอร์ที่มีไฟล์ `forest.wav` จริง หรือเปลี่ยนพาธให้ตรงกับไฟล์ของตน):

```powershell
curl.exe -X POST http://127.0.0.1:3000/api/ml/analyze -F "audio=@./forest.wav" -F "requestId=test-001" -F "stationId=ST-01"
```

ข้อผิดพลาดใช้ HTTP 400/413/502/503/504 และรูปแบบ:

```json
{"requestId":"test-001","error":{"code":"TIMEOUT","message":"บริการโมเดลใช้เวลานานเกินกำหนด กรุณาลองใหม่"}}
```

รหัสหลัก: `INVALID_REQUEST`, `INVALID_AUDIO`, `FILE_TOO_LARGE`, `NOT_CONFIGURED`, `CONFIGURATION_ERROR`, `MOCK_FAILURE`, `UPSTREAM_ERROR`, `UNAVAILABLE`, `INVALID_RESULT`, `TIMEOUT` ข้อความ/รายละเอียดภายในและ key ของบริการไม่ส่งกลับผู้ใช้

`GET /api/ml/config` ให้หน้าเว็บอ่าน mode, configured, timeoutMs, provisional และ limits ที่ใช้ตรวจไฟล์ร่วมกับ API ค่า configured บอกเพียงว่าตั้งค่าปลายทางแล้ว ไม่อ้างว่าบริการออนไลน์ ตรวจการเชื่อมต่อจริงเมื่อส่งไฟล์

## ข้อจำกัดและพฤติกรรม

- ค่าเริ่มต้นชั่วคราว WAV/MP3/M4A/OGG/WEBM ไม่เกิน 20 MiB อยู่ใน `audioLimits` ของ `src/lib/ml-contract.ts` แก้ที่เดียวหลังตกลงกับกลุ่ม การตรวจนามสกุล/MIME ไม่แทนการ decode เสียงซึ่งบริการโมเดลต้องทำ
- งานในเบราว์เซอร์รอ response เดียว สูงสุดตาม timeout (100–300000 ms) โมเดลที่ต้องใช้เวลานานกว่านี้ต้องเปลี่ยนเป็น job API ภายหลัง
- บันทึกไฟล์และพิกัดเสาก่อนเริ่มส่ง ผลสำเร็จสร้างรายการรอตรวจหนึ่งรายการ ส่วนกลางส่งงานเอง ไม่มี threshold แจ้งภาคสนามอัตโนมัติ
- รีเฟรช/ปิดหน้าเมื่อประมวลผล: งานถูกขัดจังหวะและลองใหม่จากไฟล์เดิมได้ ไม่ส่งซ้ำอัตโนมัติ การลองใหม่สร้าง requestId ใหม่ อาจเกิด inference ซ้ำที่ upstream แต่ไม่สร้างเหตุการณ์ซ้ำจาก response เก่า
- ใช้ Web Locks และ IndexedDB transaction ป้องกันส่งพร้อมกันในแท็บต้นทางเดียวกัน (Edge/Chrome ปัจจุบันและ localhost/secure context) ถ้าอีกแท็บยังทำงานอยู่ไม่ถือว่าขัดจังหวะ
- retry ใช้ชื่อ/พิกัด/รัศมีเสาตอนอัปโหลดเดิม แม้ปิดหรือย้ายเสาภายหลัง และใช้โหมดปัจจุบันที่เซิร์ฟเวอร์ตั้งค่า โดยผลเก่าไม่ถูกเปลี่ยนแหล่งที่มา
- ยังไม่มีบัญชีและสิทธิ์ฝั่งเซิร์ฟเวอร์สำหรับ API นี้ ใช้บนเครื่องพัฒนาตามเดิม การเปิดสู่สาธารณะต้องเพิ่ม authentication, authorization, rate limit และการเก็บข้อมูลจริงก่อน

## ตรวจรับร่วมกับผู้รับผิดชอบโมเดล ML

รัน `pnpm typecheck`, `pnpm build`, `pnpm test` ชุดทดสอบมี HTTP upstream จริงในเครื่องสำหรับตัวเชื่อม (ไม่ใช้โมเดลจริง) พร้อมกรณี timeout/ผลผิดรูปแบบ และ browser tests สำหรับ mock, คลาสใหม่, รีเฟรชระหว่างส่งและลองใหม่ เมื่อนำโมเดลจริงมา ให้ทดสอบไฟล์ตัวอย่างที่ตกลงผลไว้ทั้งเสียงที่รู้จักและไฟล์ที่ decode ไม่ได้ก่อนใช้สาธิต
