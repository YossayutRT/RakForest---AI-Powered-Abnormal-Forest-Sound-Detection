# ผลตรวจล่าสุด RakForest

รอบเตรียมโครงการให้กลุ่มและ GitHub — 24 ตุลาคม 2569 (2026-10-24)

## คำสั่งที่รันจริง

เครื่องตรวจ: Windows, Node.js 24.22.1, pnpm 11.25.0, Next.js 16.4.2 (Webpack), Microsoft Edge ผ่าน Playwright

| การตรวจ | ผล |
| --- | --- |
| `pnpm install --frozen-lockfile` ในสำเนาที่ไม่มี node_modules | ผ่าน ติดตั้ง 81 packages ตาม lockfile โดยไม่เปลี่ยน dependency versions |
| `pnpm dev --port 3200` จากสำเนานั้น | ผ่าน ใช้พอร์ตแยกจากเว็บผู้ใช้ หน้า `/login` ตอบ HTTP 200 |
| `GET /api/ml/config` จากสำเนานั้น | ผ่าน ค่าเริ่มต้น mock และ configured=true โดยไม่มี `.env.local` |
| `POST /api/ml/analyze` จากสำเนานั้น | ผ่าน HTTP 200, source=mock, label=chainsaw ด้วยไฟล์ทดสอบและเสา ST-01 |
| `pnpm typecheck` ในโครงการหลัก | ผ่าน |
| `pnpm build` ในโครงการหลัก | ผ่าน |
| `pnpm test` ในโครงการหลัก | ผ่าน 35/35 กรณีในรอบเดียว ใช้เวลาประมาณ 1.1 นาที |
| ลิงก์ relative ใน README และคู่มือหลัก | ผ่าน ตรวจพาธปลายทางของลิงก์และรูปภาพ และตรวจ anchor ของลิงก์เอกสารหลัก |
| รูปแบบค่าลับและพาธส่วนตัวในไฟล์ที่เตรียมเก็บ | ไม่พบรูปแบบ token/private key ที่ตรวจ หรือพาธชื่อผู้ใช้/โฟลเดอร์โครงการแบบตายตัว |
| ไฟล์ขนาดใหญ่ | ไม่พบไฟล์ตั้งแต่ 50 MiB ไฟล์ใหญ่สุดคือ thailand.geojson ประมาณ 3.02 MiB |

สำเนาสำหรับเริ่มงานมี source/config/docs เหมือนโครงการ แต่ไม่มี dependencies, build, ผลทดสอบ หรือ env ที่ใช้จริง ติดตั้งแยกจาก node_modules เดิม การวางสำเนาไว้ใต้โครงการทำให้ Next.js แจ้งเตือนว่าพบ lockfile หลายตำแหน่ง แต่หน้าเว็บและ API ผ่านการตรวจ สำเนาและเซิร์ฟเวอร์ตรวจถูกนำออกหลังตรวจเสร็จ

Lockfile เดิมและหลังตรวจมี SHA256 ตรงกัน:

```text
441e11618d152f5f16b682e329abaae7e6469bcfa59bbcbce53525559adca5f7
```

## ชุดทดสอบครอบคลุมอะไร

- อัปโหลด → ส่งงาน → จำลองส่งข้อความล้มเหลว/ลองใหม่ → ภาคสนามรับทราบ → ส่งผลพร้อมภาพ → ส่วนกลางปิดงาน
- ไฟล์ผิด การวิเคราะห์ล้มเหลว การบันทึกล้มเหลว ข้อมูลว่าง และการเก็บไฟล์หลังรีเฟรช
- เสาในประเทศไทยรวมเกาะ ปฏิเสธจุดต่างประเทศ รหัสซ้ำ ปิดเสา และรักษาพิกัดเหตุการณ์เก่าหลังย้ายเสา
- ย้ายข้อมูล v1/v2 โดยรักษางาน เสาที่เพิ่มไว้ และ attachments
- ตัวเชื่อม HTTP กับ upstream ทดสอบในเครื่อง: multipart/key, คลาสใหม่, บริการล่ม, timeout, HTML/JSON ผิดรูปแบบ และคะแนนผิดสเกล
- หน้าภาพรวม: ตัวเลข หมุด ตัวกรอง รายละเอียดงาน แท็บจอเล็ก รายการ 30 งาน และการเลื่อนเฉพาะแผงด้วยคีย์บอร์ด
- จอ 390/768/1366/1920px, layout คอม 1366×768 และ 1920×1080, การขยายข้อความ 200%, พื้นที่จัดวางเทียบเท่า browser zoom 200%, โฟกัส/กล่องโต้ตอบ และความต่างสีของข้อความ/สถานะตัวแทน

## ขอบเขตของผลตรวจ

มี API ตัวกลาง ML และตัวเชื่อม HTTP แล้ว แต่ยังไม่ได้ทดสอบกับโมเดลจริงของกลุ่ม Telegram ยังจำลอง บัญชีจริง/สิทธิ์ server/ฐานข้อมูลร่วมยังไม่เชื่อมต่อ การทดสอบใช้ browser profiles แยกจากข้อมูลผู้ใช้ และแทนที่ OSM tiles ไม่ยืนยันความพร้อมของบริการแผนที่ภายนอก

การตรวจแพตเทิร์นค่าลับไม่ใช่การรับรองว่าไม่มีข้อมูลอ่อนไหวทุกชนิด ต้องตรวจไฟล์และ `git diff --cached` อีกครั้งเมื่อกลุ่มเลือกอัปโหลดจริง ไม่ได้สร้าง Git repository, commit, remote หรือ push ในรอบนี้ และยังไม่ได้กำหนด LICENSE ให้โค้ด
